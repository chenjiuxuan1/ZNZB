# 统一看板清单与 DS 调度监控单页优化设计

## 背景

当前平台将 Metabase 看板拆成两类数据：

- `inventory.dashboards`：已经发现卡片、可直接执行查询的看板。
- `panelSources`：业务已经录入，但尚未发现卡片的内部 Metabase 看板。

“看板与卡片”可以看到两类数据的计数，但规则试跑、手动巡检、定时巡检配置等页面只读取 `inventory.dashboards`。因此新录入的六国提前还款看板虽然显示为“已标记”，却不会出现在其他功能入口。

DS 调度监控当前是单页，但监控项目、Token、检查结果和运行配置缺少明确层次，视觉组件也未复用 Metabase 定时巡检页面的现有设计语言。

## 目标

1. 所有已录入的 Metabase 看板在平台各入口使用同一份统一清单。
2. 未发现卡片的看板也能展示和选择，但必须明确标记为“待发现”，禁止执行依赖卡片的操作。
3. 获得 Metabase 登录态并发现卡片后，同一个看板自动升级为“可执行”，不产生重复项。
4. DS 调度页保持单页结构，视觉和交互复用 Metabase 定时巡检页面。
5. DS 定时巡检能够选择国家项目，通知信息直接继承 Metabase 配置。

## 非目标

- 不增加 DS 四页签。
- 不修改全局侧边栏和平台品牌样式。
- 不在本次工作中修改 Metabase 看板本身。
- 不增加独立的 DS 通知配置副本。

## 统一看板模型

平台 API 在返回 inventory 时，将 `panelSources` 归一化并合并进 `dashboards`，每个条目包含：

- `countryCode`、`countryName`、`timezone`
- `sourcePanelId`、`sourcePanelTitle`
- `title`、`url`
- `access`: `public` 或 `internal`
- `availability`: `ready` 或 `pending_discovery`
- `cards`: 已发现时为卡片列表，待发现时为空数组
- `executable`: 是否允许查询与规则试跑
- `pendingReason`: 待发现原因

合并键依次使用国家、内部 dashboard ID/public UUID、URL、sourcePanelId。已发现 inventory 优先，来源数据只补充缺失字段。这样同一看板不会同时显示“可执行”和“已标记”两条记录。

## 各功能入口行为

### 看板与卡片

- 左侧统一展示所有看板。
- 使用状态徽标区分“可执行”和“待发现”。
- 可执行看板展示卡片详情。
- 待发现看板展示来源链接、待发现原因和所需登录态。

### 规则试跑

- 国家与看板下拉包含全部统一看板。
- 待发现看板可以查看，但卡片选择和试跑按钮禁用。
- 页面明确提示需要先完成 Metabase 卡片发现。

### Metabase 手动巡检

- 看板选择器展示全部统一看板。
- 待发现项不可作为单看板执行目标。
- “扫描国家全部看板”运行时，服务端实时发现来源，并把新发现看板与缓存 inventory 合并。

### Metabase 定时巡检

- 国家卡片的看板数量使用统一清单。
- 单看板选择器只允许选择可执行看板。
- 不选择具体看板时，按国家运行会实时发现并扫描所有来源。

### 总览、通知和历史

- 总览看板数量展示统一清单总数，并分别展示可执行/待发现数量。
- 巡检结果、通知和历史仍只统计实际执行过的看板，避免把待发现项误报为查询失败。

## DS 调度监控单页设计

页面从上到下分为四个连续区域，但不使用页签：

1. **状态概览**：复用 Metabase hero 和统计卡，显示监控国家、启用项目、在检工作流、卡死、离线、上次运行。
2. **监控项目配置**：六个国家使用 Metabase 的国家配置卡。每张卡包含启用开关、项目名称、项目码和解析状态。Token 放入统一的“高级连接配置”折叠区。
3. **定时巡检配置**：复用 Metabase schedule panel，包含总开关、巡检间隔、下次运行、按国家项目开关。每个国家只运行已经启用且配置项目码的项目。
4. **最近检查结果**：使用现有表格和状态徽标展示异常工作流；无结果时提供清晰空态。

页面不使用大尺寸 emoji，不新增另一套颜色、阴影或圆角规范。

## DS 数据流

- `GET /api/ds-scheduler/config` 返回项目配置、定时配置摘要和继承后的 Metabase 通知摘要。
- `PUT /api/ds-scheduler/config` 保存国家项目、项目码、Token 和启用状态。
- DS 定时任务读取启用国家，将对应 `project_code` 传给 n8n 网关。
- 通知渠道、bot、接收人和 mentions 每次运行时从 Metabase 定时巡检配置读取。
- 项目名称解析失败时保留原项目码，并返回逐国家错误，不显示虚假的成功状态。

## 错误处理

- 统一 inventory 合并失败时保留已加载部分，并返回来源级错误。
- 待发现看板不会触发规则试跑请求。
- DS 国家未配置项目码时不能启用定时巡检，并显示就地校验信息。
- DS Token 不在普通项目卡中明文展示。
- Metabase 通知未配置时，DS 页面显示“继承配置不完整”，并链接到 Metabase 定时巡检配置区域。

## 测试与验收

- API 测试：来源看板会合并进统一 dashboards；已发现项不会重复。
- 页面数据测试：inventory、sandbox、batch-check 使用同一统一清单。
- 巡检测试：待发现项不会被当作查询失败；国家巡检会实时发现新增来源。
- DS 测试：项目启用状态、项目码保存、定时范围和 Metabase 通知继承。
- 语法、JSON 配置、全量 Node 测试通过。
- 人工验收：
  - 六国提前还款看板均出现在“看板与卡片”。
  - 六国看板在规则试跑和巡检配置中可见，并正确区分是否可执行。
  - DS 页面保持单页且与 Metabase 页面视觉一致。
  - 可以配置国家项目并加入定时巡检。
