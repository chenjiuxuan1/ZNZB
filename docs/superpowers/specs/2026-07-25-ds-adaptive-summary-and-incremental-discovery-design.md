# DS 自适应巡检、汇总通知与增量发现设计

## 目标

1. DS 仅在 ONLINE 定时任务跨过一个完整调度周期仍未运行时报告“旷工”。
2. DS 结果并入 Metabase 定时巡检的最终值班汇总，不再发送独立 DS 告警。
3. 六国看板批量发现只补齐待发现看板，已有可执行卡片的看板不重复请求 Metabase。
4. 修复本轮发现的明确可靠性与安全问题，并用自动化测试防回归。

## DS 自适应旷工判定

- n8n 的 `check_failed_instances` 响应扩展为每个任务返回：调度表达式或周期、调度时区、最近一次运行时间、下次应运行时间及逾期状态。
- n8n 在 DolphinScheduler 数据源侧解析调度配置；Node 服务不自行解释 cron 方言。
- 仅对 `ONLINE` 任务判断旷工。任务在其最近一次运行后已跨过完整的下一调度周期、且仍没有新运行实例时，才标记为旷工。
- DS 结果保留调度周期、最后运行和逾期说明，供管理页和汇总通知使用。OFFLINE 任务继续排除。

## 汇总通知

- 批量 Metabase 巡检启用 DS 时，同一轮将 DS 结果传入最终“今日值班”消息。
- `2.DS调度` 按国家生成简洁摘要：检查任务数、卡死数、旷工数、检查失败状态；异常国家额外列出受影响任务名。
- 移除批量巡检过程中调用独立 `notifyDsSchedulerCheck` 的路径。DS 页面中的手动检查保留查看结果能力，但不再自动外发独立报告。
- 独立 DS 通知配置及测试接口保留用于兼容，但业务巡检不会使用它发送告警。

## 看板增量发现

- “一键发现六国看板”首先从 inventory 和来源面板确定每国待发现看板。
- 无待发现看板的国家返回 `skipped`，不会调用 Metabase；批量结果同时显示成功、跳过与失败数量。
- 只对待发现来源执行发现，将结果和既有 inventory 合并后原子写回；已可执行的看板及其卡片保持不变。
- 单国家“重新发现”继续作为显式强制刷新操作，保留当前行为。
- 单个国家失败不会阻断其他国家，前端只展示实际失败国家的错误详情。

## 测试与审查

- 先为 DS 逾期信息、汇总文案、独立通知抑制和增量发现分别增加失败测试，再实现最小改动。
- 覆盖月度任务、每日任务、OFFLINE 任务、部分国家失败和全量已发现等边界。
- 审查服务端路由输入验证、外部请求超时、错误信息泄露、敏感字段脱敏与批量并发限制；仅修复可复现或可静态确认的问题。

## 验收

- 月度任务在未跨越下一完整月度周期时不告警。
- 一轮批量巡检只发送一份最终值班汇总，且其中包含 DS 国家摘要。
- 已发现六国看板时，批量发现不访问 Metabase 且页面显示跳过而非失败。
- 自动化测试全部通过，审查发现与修复结果在交付中说明。
