# 看板级两阶段 AI 取证漏斗设计

## 目标

将一次巡检产生的大量异常指标压缩为少量看板级首轮请求，同时保留每个指标的独立判断能力。首轮负责汇总和保守筛选，二轮只深挖确有问题或证据不足的指标。全过程继续限制 Dify 实际并发，且只有 AI 结论全部收敛后才发送最终通知和写入最终历史。

## 核心流程

1. 完成国家巡检和 DS 调度核查，生成仅内部可见的待完成巡检记录。
2. 按 `国家 + dashboardUuid` 聚合异常。一个异常看板的全部异常指标进入同一个首轮 Dify 请求，不按底表或每三条拆分。
3. 首轮为看板读取和复用公共证据，输出看板摘要，并为每个输入 `anomalyIndex` 返回且只返回一个初步结论：
   - `verified_normal`：实时证据明确证明指标没有异常。
   - `suspected_issue`：证据明确指向数据问题。
   - `needs_deep_analysis`：证据不足、工具失败、指标字段不明确或存在冲突。
4. `verified_normal` 直接形成最终“AI 核验无异常”记录；它不会进入第二轮，也不会进入异常通知。
5. `suspected_issue` 和 `needs_deep_analysis` 各自生成一个单指标二轮任务。二轮可使用首轮公共快照，并针对当前指标补查底表字段、维度、血缘、Wattrel 和 DS 实例，输出独立最终根因。
6. 所有二轮任务完成、失败或超时后，平台才生成最终通知和最终历史。

## 准确性边界

首轮是保守筛选器，不是模糊分类器。只有实时底表值、DS 完成时序或其他可审计证据明确证明告警为误报时，才能输出 `verified_normal`。以下情况一律进入二轮：

- 没有查询到指标对应字段或维度；
- 工具失败、超时或只返回空结果；
- 公共证据只能证明看板或底表整体正常，不能证明具体指标正常；
- 多个指标共享底表但计算口径不同；
- Dify 未给所有输入 `anomalyIndex` 返回唯一结论。

二轮必须以单个指标为调查边界。一个指标的查询结果不得用于直接判断另一指标。二轮最终允许 `data_issue`、`business_change`、`verified_normal`、`insufficient_evidence`；后两种中只有 `verified_normal` 不通知，`insufficient_evidence` 必须保守通知为“AI 未核验”。

## 调用与资源限制

- 首轮请求单位：一个国家的一个异常看板，包含该看板全部异常指标。
- 二轮请求单位：一个异常指标。
- 首轮和二轮共用同一个全局调度器，Dify 实际运行并发硬限制为 2。
- 平台不会把待处理任务预先全部投递给 n8n；只有某个在途任务 callback 回写、失败或超时后，才释放下一个任务。
- 首轮 Agent 最多 8 次迭代、6 次公共工具调用；已在平台快照中的证据不得重复查询。
- 二轮 Agent 最多 8 次迭代、6 次补充工具调用。
- 单任务等待上限 10 分钟；整轮目标 20 分钟、硬截止 30 分钟。达到硬截止后不再提交新任务，未完成指标写为 `insufficient_evidence / AI 未核验`。
- 看板指标数量不设三条上限。首轮请求体硬限制为 512 KiB；超过限制时不截断、不调用 Dify，该看板全部指标直接标记为 `insufficient_evidence / AI 未核验` 并保守通知，避免超大请求压垮单机服务。

## 数据协议

### 首轮请求

首轮请求包含 `runId`、`countryCode`、`dashboardUuid`、`dashboardTitle`、`snapshotId` 和完整 `cases`。每个 case 包含 `anomalyIndex`、卡片/指标信息、异常原文及必要规则上下文。

首轮返回：

```json
{
  "action": "finish",
  "dashboardSummary": "看板级证据和总体判断",
  "verdicts": [
    {
      "anomalyIndex": 0,
      "screeningVerdict": "verified_normal|suspected_issue|needs_deep_analysis",
      "summary": "当前指标初判",
      "evidence": ["可审计证据"],
      "limitations": "证据边界"
    }
  ]
}
```

平台严格校验结果数量、索引唯一性和索引集合。任何缺失、重复或越界结果都会使该看板全部指标进入二轮，不会接受格式异常响应中的局部“正常”判断，也不会静默丢弃。

### 二轮请求

二轮请求包含单个 case、首轮看板摘要、公共快照 ID 和该指标首轮证据。最终返回现有完整分析结构，并新增 `verified_normal` 作为明确正常结论。

## 通知与历史

最终通知仅包含：

- `data_issue`：按每个异常指标展示各自原因；
- `insufficient_evidence`：展示“AI 未核验”和限制原因。

`verified_normal` 和 `business_change` 不作为数据故障播报。最终历史仍保存全部原始规则异常、首轮看板总结、逐指标首轮判断、二轮分析结果、查询方式、证据和限制。前端在看板级别先显示 AI 总结，再在指标下显示最终状态与原因。

## 失败处理

- 首轮请求失败：该看板全部指标进入二轮，不判正常。
- 首轮结果数量、索引或结构错误：该看板全部指标进入二轮，不接受局部“正常”结果。
- 二轮失败或超时：对应指标标记“AI 未核验”，不影响其他指标完成。
- n8n callback 重复：按 jobId 和阶段幂等处理。
- 服务重启：待完成巡检、任务阶段和已完成结果从持久化文件恢复；不得重复投递已完成任务。
- 达到 30 分钟截止：停止新投递，收敛为保守通知和完整审计记录。

## 兼容与启用

旧单指标手工重新分析接口继续保留。两阶段协议通过新的显式开关启用；在新版 ZNZB、n8n JSON 和 Dify DSL 全部导入并发布前，服务器继续使用现有流程。启用顺序必须是工具提供者、Dify DSL、n8n 工作流、ZNZB 代码，最后打开两阶段开关。

## 验收标准

- 同一国家同一异常看板只产生一个首轮 Dify 请求，并包含该看板全部异常指标。
- 首轮必须为每个指标返回唯一初判；无明确正常证据的指标全部进入二轮。
- 二轮每个请求只包含一个指标，并返回该指标独立原因。
- 任意时刻实际在 Dify 运行的首轮与二轮任务合计不超过 2。
- 未收到 callback 前不投递替代任务，不发送最终通知，不写最终历史。
- AI 正常和业务变化不进入数据异常播报，但完整保留在历史审计。
- 30 分钟后停止继续提交，不发生无限队列或任务风暴。
