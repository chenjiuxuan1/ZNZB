# 告警中心生命周期化改造设计

## 目标

将当前分散在“告警中心、告警注册、规则配置、规则试跑、通知预览、DS 失败任务日志”等页面中的告警能力，按告警生命周期整合为一个统一入口。改造必须保留全部现有功能，并补齐来源降级、生产操作保护、权限、审计、响应式和无障碍能力。

## 设计原则

1. 用户按工作任务进入功能，不要求先理解 Nightingale、n8n、DolphinScheduler 或自定义脚本。
2. 第一阶段复用现有后端能力，避免同时重写界面和核心生产逻辑。
3. 旧入口保留兼容跳转，完成逐项验收后再删除重复实现。
4. 任一来源失败不能让整个告警中心失明，也不能把请求失败展示成“0 条告警”。
5. 所有生产写操作必须说明影响范围、校验权限并记录审计信息。
6. 功能迁移以对照清单为准，不能以“页面已经能打开”作为完成标准。

## 信息架构

统一入口使用以下路由：

```text
#/alerts/overview       总览
#/alerts/events         事件
#/alerts/rules          规则
#/alerts/notifications  通知
#/alerts/operations     运维
```

`#/alerts` 默认进入 `#/alerts/overview`。

```text
告警中心
├─ 总览：当前风险、严重告警、通知失败、待处理事项
├─ 事件：活跃告警、历史告警、DS 失败与自动修复记录
├─ 规则：夜莺规则、n8n 告警链路、自定义告警条目
├─ 通知：渠道、接收人、路由、送达记录
└─ 运维：连接状态、测试、发布记录、审计日志
```

### 旧入口兼容

以下页面第一阶段继续可用：

- `#/alert-registry`
- `#/rules`
- `#/sandbox`
- `#/notify-preview`
- `#/ds-scheduler`
- `#/ds-failure-logs`
- `#/wattrel-alerts`

旧页面顶部增加迁移提示和新页面跳转。旧 URL 不立即失效，书签和历史链接继续可用。只有在对应功能完成迁移、自动化测试和人工验收后，才能从侧边栏移除旧入口。

## 页面设计

### 总览

总览按行动优先级展示，不以资产数量作为首要内容。

第一层“需要立即处理”：

- 未恢复的严重告警。
- 通知发送失败。
- 自动修复失败或等待人工介入。

第二层“风险趋势”：

- 按国家聚合。
- 按业务组聚合。
- 按告警来源聚合。

第三层“来源健康与资产摘要”：

- Nightingale、n8n、DolphinScheduler、自定义告警的健康状态。
- 规则、工作流、渠道、接收人等资产数量。

每个待处理事项必须能进入事件详情，并展示责任人、通知结果、自动修复状态和下一步操作。

### 事件

事件页统一承载：

- Nightingale 活跃告警和历史告警。
- n8n 告警执行及失败节点。
- DolphinScheduler 失败任务、任务日志和重跑结果。
- 自动修复过程和最终状态。
- 多国一致性校验结果。

筛选维度包括时间范围、状态、国家、业务组、级别、来源和规则名称。事件详情使用时间线串联“触发、通知、修复、恢复”。现有筛选、分页、展开详情、执行节点、任务日志和重跑功能必须保留。

### 规则

规则页提供统一列表和来源筛选，来源包括：

- Nightingale 告警规则。
- n8n 告警链路。
- 自定义告警注册条目。

列表统一显示名称、来源、国家、状态、触发方式、通知摘要和最近一次执行。详情继续使用来源特有编辑器，避免用一个通用表单抹平 PromQL、SQL、n8n 节点和脚本模板之间的差异。

夜莺监控目标和数据源作为规则上下文入口保留。自定义告警的新增、编辑、删除、启停、测试、脚本预览和代码更新能力全部迁入。

### 通知

通知页统一展示：

- 电话、钉钉、KN Chat、TV 和其他已启用渠道。
- 接收人、固定号码、机器人、群、@成员和国家负责人。
- 通知规则与告警规则的关联关系。
- 通知发送记录和失败原因。
- 通知文案预览与测试。

共享通知规则必须显示影响范围。修改前展示关联告警数量和规则名称。清理失效接收人前展示变更清单；清理后如果规则变成零接收人，必须阻止直接提交或要求同步停用该规则。

### 运维

运维页承载高风险和平台级能力：

- Nightingale、n8n、DolphinScheduler 连接状态。
- 规则试跑和模拟告警。
- 真实通知测试和电话测试。
- 脚本预览、代码提交和目标机部署。
- n8n 定时配置。
- 操作审计与发布记录。

“更新代码”拆成脚本预览、提交代码、部署目标机三个显式步骤。任何一步失败时显示已完成步骤和恢复方式，不能用一个模糊的失败提示覆盖全链路状态。

## 数据模型与来源降级

所有聚合读取结果采用统一来源状态：

```js
{
  source: "nightingale" | "n8n" | "dolphinscheduler" | "registry",
  sourceStatus: "loading" | "healthy" | "degraded" | "failed",
  updatedAt: 0,
  lastSuccessAt: 0,
  stale: false,
  retryable: true,
  data: null,
  error: null
}
```

Nightingale、n8n、DolphinScheduler 和自定义告警分别加载。一个来源失败时：

1. 其他来源继续展示。
2. 失败区域展示最后成功数据。
3. 数据标注“已过期”及最后成功时间。
4. 提供单来源重试。
5. 依赖该来源的写操作禁用。

缓存只用于保留最近一次成功读取，不得作为写操作的配置真值。

## 交互状态

| 页面 | 加载 | 空状态 | 错误 | 成功 | 部分失败 |
|---|---|---|---|---|---|
| 总览 | 分来源骨架 | 当前无待处理事项 | 来源错误卡 | 风险与任务队列 | 可用数据继续展示，失败来源标记过期 |
| 事件 | 筛选器可用，列表骨架 | 提供清除筛选入口 | 列表内重试 | 事件与时间线 | 失败来源独立折叠 |
| 规则 | 保留最近列表，禁用写入 | 引导创建或调整筛选 | 显示来源连接错误 | 查看和编辑 | 仅禁用异常来源操作 |
| 通知 | 渠道分别加载 | 引导创建接收人与路由 | 标记失败渠道 | 路由与送达状态 | 保留最近成功配置 |
| 运维 | 健康检查逐项返回 | 提示尚未配置 | 错误摘要与恢复建议 | 连接、测试、发布记录 | 单项重试，不阻塞整页 |

## 权限与生产操作保护

### 角色

- `viewer`：查看、筛选、展开详情和复制内容。
- `operator`：包含 viewer 权限，并可认领、重试、修改接收人、启停规则和工作流。
- `admin`：包含 operator 权限，并可删除、执行命令、真实拨号、提交代码和部署。

### 风险等级

| 风险 | 操作 | 保护 |
|---|---|---|
| 低 | 查询、筛选、查看详情、复制 | 直接执行 |
| 中 | 修改规则、通知人、定时、启停 | 影响范围预览和二次确认 |
| 高 | 删除、真实拨号、执行命令、提交和部署 | admin 权限、确认词、预览和审计 |

所有写操作统一通过动作保护层：

1. 检查登录用户和角色。
2. 检查目标来源健康状态。
3. 展示修改对象、目标系统和影响范围。
4. 高风险操作要求输入对象名称或“确认发布”。
5. 生成操作编号并记录操作者、时间、前后差异和结果。
6. 部分成功时返回分步骤结果和恢复入口。

### 必须纠正的现有行为

- 脚本预览必须只读，不能为了预览先保存配置。
- “测试”必须区分模拟测试和真实发送。
- 电话测试必须显示号码、模板和真实计费提示。
- 代码提交与 SSH 部署不能由一个不可拆分的按钮连续执行。
- 共享通知规则修改前必须展示全部受影响告警。

## 前端代码边界

新页面按职责拆分，避免继续扩充现有单文件：

```text
web/src/views/alert-center/
├─ index.js
├─ overview.js
├─ events.js
├─ rules.js
├─ notifications.js
├─ operations.js
├─ shared/
│  ├─ lifecycle-nav.js
│  ├─ source-state.js
│  ├─ action-guard.js
│  ├─ pager.js
│  └─ modal.js
└─ legacy-adapters/
```

第一阶段保留 `src/alert-center.mjs` 和 `src/alert-registry.mjs` 的既有业务函数。新增聚合接口只负责组合和标准化，不复制 Nightingale、n8n 或 DS 客户端逻辑。

## 响应式与无障碍

- 视口宽度不小于 1280px 时显示横向生命周期导航和完整表格，详情使用右侧抽屉。
- 768–1279px 时导航可横向滚动，次要列进入详情。
- 小于 768px 时表格改为列表，筛选器进入底部面板。
- 所有可操作区域不小于 44px。
- 长规则名、邮箱、Webhook 和日志允许换行或复制，不能产生页面横向溢出。
- 生命周期导航使用 `role="tablist"` 并支持方向键。
- 弹窗和抽屉支持焦点锁定、Esc 关闭和关闭后焦点返回。
- 告警级别同时使用文字、图标和颜色。
- 加载和操作结果使用 `aria-live`。
- 正文对比度不低于 4.5:1。
- 尊重 `prefers-reduced-motion`。

## 功能保留清单

迁移验收必须覆盖：

- 实时告警、业务组聚合和告警详情。
- 历史告警筛选、分页和触发记录展开。
- n8n 失败执行、失败节点和执行详情。
- Nightingale 规则编辑、启停和通知配置。
- 监控目标和数据源查看。
- 通知全景、共享关系和失效接收人治理。
- n8n 工作流详情和启停。
- 自定义告警新增、编辑、删除、启停和测试。
- 多国校验结果、定时、群通知、负责人和电话配置。
- DS 失败查询、自动重跑、修复记录和通知进程。
- 通知文案预览和真实发送测试。
- 脚本预览、代码提交和目标机部署。

每项功能都要验证正常、加载、空数据、来源错误、部分失败和无权限状态。

## 分阶段交付

### 阶段一：新外壳与兼容导航

- 建立五个生命周期路由和统一导航。
- 为旧 URL 增加兼容入口。
- 抽取共享分页、弹窗、来源状态和操作保护组件。
- 不改变现有生产写接口。

### 阶段二：总览与事件

- 将当前告警、历史告警、n8n 执行和 DS 修复记录迁入。
- 实现来源独立降级和最近成功数据。
- 建立事件详情时间线。

### 阶段三：规则与通知

- 统一 Nightingale、n8n 和自定义告警资产入口。
- 合并重复的通知规则编辑入口。
- 增加共享影响范围和失效接收人保护。

### 阶段四：运维、安全与审计

- 加入 viewer、operator、admin 权限。
- 拆分模拟测试、真实发送、代码提交和部署。
- 建立操作审计与分步骤结果。

### 阶段五：验收与旧实现下线

- 对照功能保留清单完成自动化和人工验收。
- 保留一个发布周期的兼容路由。
- 只有确认无功能缺失后才移除旧侧边栏入口和重复实现。

## 测试策略

1. 为路由和生命周期导航编写 DOM 测试。
2. 为来源状态标准化和部分失败编写单元测试。
3. 为每个现有功能建立迁移对照测试，验证旧入口与新入口调用相同业务能力。
4. 为 viewer、operator、admin 的允许和拒绝路径编写权限测试。
5. 为中高风险动作编写影响预览、确认和审计测试。
6. 为 Nightingale、n8n、DS 单独失败及同时失败编写聚合测试。
7. 使用浏览器测试覆盖桌面、平板和移动端，不允许横向溢出。
8. 发布前运行完整 `npm test`，并人工验证真实系统的只读路径；真实拨号和部署使用明确的受控测试对象。

## 不在本次首轮范围

- 不重写 Nightingale、n8n 或 DolphinScheduler 客户端。
- 不改变各系统现有规则语义。
- 不在第一阶段删除旧 URL。
- 不引入新的前端框架。
- 不自动执行真实电话、通知或生产部署作为常规浏览器测试。

## 成功标准

1. 用户从告警中心五个入口可以找到全部现有功能。
2. 同一对象只有一个主要编辑入口，其他位置只提供查看和明确跳转。
3. 单个来源故障时，其余来源仍可使用，且陈旧数据不会被误认为实时数据。
4. 未授权用户不能执行生产写操作。
5. 高风险操作可预览、可追踪、可恢复。
6. 功能保留清单全部通过，旧入口在兼容期内仍然可用。
