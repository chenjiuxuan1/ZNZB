# 告警中心规则链路与运维工作台纠偏设计

## 背景与根因

生命周期化第一阶段把部分“能力归属”实现成了旧页面地址映射：`n8n 告警链路`被映射到 Metabase 巡检规则页 `#/rules`，运维区的连接状态、脚本预览、提交发布和审计记录则全部映射到 `#/alert-registry`。这些页面虽然包含少量相关操作，但并不等价，导致用户进入错误上下文，也让运维页退化为空白跳转中心。

本次修复不删除任何旧能力，不改变既有生产接口的默认行为。目标是纠正入口语义，并让 `#/alerts/operations` 成为可直接工作的运维页面。

## 产品归属

### 规则页

- Nightingale 告警规则、监控目标和数据源继续由 `#/alerts/rules` 管理。
- n8n 告警工作流由 `#/alerts/rules` 管理。`n8n 告警链路`入口使用 `#/alerts/rules?focus=n8n-workflows`，页面完成加载后滚动并高亮 n8n 工作流区。
- Metabase 定时巡检规则继续保留在 `#/rules`，名称明确为“Metabase 巡检规则”，不得作为 n8n 的目标页。
- 自定义告警条目和 DS 监控调度继续使用原成熟页面，但入口文案明确其真实能力。

### 运维页

`#/alerts/operations` 改为四个可用区域，而不是跳转集合：

1. **连接状态**：调用 `/api/alerts/health`，分别展示 Nightingale 与 n8n 的正常、异常、未配置状态，支持单次整页刷新。单一来源失败不隐藏另一来源。
2. **测试与验证**：区分“Metabase 规则沙盒”和“自定义告警 dry-run”。前者进入 `#/sandbox`；后者进入带运维上下文的告警注册页。文案必须说明 dry-run 不发送通知。
3. **脚本与发布**：列出支持脚本模板的告警条目。用户先选择条目，再执行只读预览；发布必须经过明确确认，继续复用现有 `preview-script` 与 `apply-script` 接口。页面不能自动发布，也不能把预览与保存配置绑定。
4. **运维记录**：展示告警条目测试记录以及新产生的脚本预览/发布审计。测试记录标注为“执行记录”，不能称作发布记录。

## 数据与接口

### 复用接口

- `GET /api/alerts/health`：连接状态。
- `GET /api/alert-registry`：可运维告警条目。
- `POST /api/alert-registry/:id/preview-script`：只读脚本预览。
- `POST /api/alert-registry/:id/apply-script`：提交与部署。
- `GET /api/alert-registry/history`：告警条目测试/定时执行记录。

### 发布审计

在告警注册模块新增独立的脚本操作审计存储和读取接口。每次预览与发布记录以下字段：

- 操作编号、条目 ID、条目名称、操作类型。
- 开始时间、结束时间、最终状态。
- Git 与部署的分步骤结果摘要。
- 失败信息；不得记录密钥、完整脚本内容或环境变量值。

发布接口无论成功、失败或部分成功都写入审计。预览只记录元数据和 diff 摘要。新增 `GET /api/alert-registry/script-audit` 供运维页读取最近记录。

## 页面交互

- 规则页接收 `focus` 参数。目标区不存在或加载失败时保留页面内容并显示非阻塞提示。
- 运维页首次进入并行加载健康状态、告警条目、执行历史和脚本审计，各区域独立显示加载、空态和错误态。
- 只有配置了脚本模板或脚本路径的条目进入“脚本与发布”选择列表；没有可发布条目时给出明确空态。
- 脚本预览不会先保存编辑内容，只读取当前已保存条目。
- 发布按钮默认不可用，完成条目选择和脚本预览后才可点击；确认框显示条目、仓库文件和目标机影响。
- 发布结果逐项展示渲染、仓库写入、Git 提交推送和目标机部署状态。部分成功不得显示为全部成功。
- 旧页面继续保留，并通过带语义的深链作为补充入口，不自动执行任何写操作。

## 错误与生产安全

- 健康检查错误直接展示来源返回的脱敏错误摘要，并提供刷新。
- 预览失败不开放发布；发布失败保留预览和分步骤结果，方便人工恢复。
- 所有动态文本经过转义；审计响应过滤潜在凭据和完整命令输出。
- 本次不新增自动重试、自动提交或自动部署。

## 测试与验收

先写失败测试，再实现：

1. 生命周期模型断言 n8n 链路不再指向 `#/rules`，而是带焦点参数的规则页。
2. 规则页焦点解析、目标区标识和加载后聚焦行为。
3. 运维页存在连接状态、测试、脚本发布、运维记录四个真实区域，不再渲染空白占位。
4. 健康接口的正常、异常和未配置状态渲染。
5. 脚本预览不会触发条目保存；未预览不能发布。
6. 发布需确认，并正确呈现成功、失败和部分成功结果。
7. 脚本预览与发布审计可持久化、排序和脱敏。
8. 运行告警中心、告警注册、服务端路由和全量测试；再用浏览器验证桌面及窄屏路径。

## 非目标

- 不删除旧侧边栏页面。
- 不重写 Nightingale、n8n、Metabase 或 DolphinScheduler 客户端。
- 不在本次引入完整账号角色系统。
- 不把通知测试、电话测试或 DS 网关策略强行合并到一个通用操作按钮。
