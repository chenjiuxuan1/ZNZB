# 告警注册控制台视觉与安全优化设计

## 背景

当前“告警注册”页面承担条目管理、多国一致性校验、消息模板、通知配置、电话语音配置和历史结果等高密度运维操作。现有页面存在信息层级不清、浅灰容器嵌套过多、控件对齐不一致、操作按钮与作用对象距离过远、开关与标签分离、宽屏留白过大及窄屏拥挤等问题。

本次优化在不改变现有业务能力和接口契约的前提下，将整页整理为紧凑、清晰、克制的专业运维控制台，并同步检查可直接验证的安全风险。

## 范围

### 包含

- “告警注册”整页视觉层级、间距、排版和交互状态统一。
- 告警条目列表、工具栏、测试结果、多国一致性校验、通知配置、消息模板、电话语音配置和历史结果区域。
- 表单标签、输入框、文本域、选择器、复选框、开关、按钮、状态提示和折叠面板。
- 宽屏与窄屏响应式布局、键盘焦点态、禁用态、错误态和保存反馈。
- 与本页相关的 DOM 输出、输入校验、敏感信息、接口访问和命令执行风险检查。
- 依赖审计和现有测试回归。

### 不包含

- 更改告警规则含义、通知阈值、调度策略或默认接收人。
- 更换前端框架或引入新的 UI 依赖。
- 重写服务端接口或数据存储格式。
- 与告警注册页面无关的全站视觉重构。

## 方案选择

采用“结构微调 + CSS 重构”。仅修改 CSS 无法解决错误的信息层级和操作归属；整页组件化重写则会显著扩大对复杂告警逻辑的回归面。选定方案允许调整页面内部 DOM 分组和语义标记，但保留接口、字段名、事件行为和业务数据流。

## 代码同步策略

当前分支落后远端且工作区存在未提交修改。实施前先记录状态并创建可恢复备份，再将分支快进到对应远端最新提交，随后恢复本地修改并处理重叠。同步过程中不得覆盖或误提交现有数据治理文件、补丁文件和 `.claude/` 目录。

若恢复本地修改产生冲突，只处理本次范围明确涉及的文件；无法可靠判断归属的冲突停止处理并保留双方内容。

## 页面设计

### 页面骨架

- 页头保留页面名称和简短说明，主要操作集中在右侧工具栏。
- 各业务区域使用单层面板，不再叠加多层相近的浅灰背景。
- 面板标题、说明、状态和操作形成一致的头部结构。
- 高风险或低频设置继续使用折叠面板，默认展开状态沿用现有行为。

### 信息层级

- 一级：页面标题与全局操作。
- 二级：告警条目、测试结果、多国一致性校验等业务区域。
- 三级：消息模板、通知渠道、电话语音等配置组。
- 辅助说明降低对比度，但保证可读性；关键状态通过文字、图标和颜色共同表达，避免只依赖颜色。

### 消息模板区域

- 标题行展示用途，并将可编辑提示作为次要信息。
- 可用变量展示为紧凑标签，可读、可复制且允许换行。
- 异常消息模板使用带明确标签的等宽文本编辑区。
- 无异常提示使用单行输入布局。
- 启用开关与含义文本绑定，放在操作栏左侧；保存按钮放在右侧，明确属于整个模板配置。
- 保存中、成功、失败状态在操作栏就近展示，避免布局跳动。

### 通知与语音配置

- 国家、负责人、联系人、渠道和阈值建立稳定列关系。
- 宽屏使用对齐的网格；窄屏转为带字段标签的分组卡片。
- 密钥输入不回填明文，掩码说明与输入控件保持清晰关联。
- 测试拨打与正式保存视觉分级，危险或外部副作用操作有明确提示。

### 控件与状态

- 统一高度、圆角、边框、字体和焦点环。
- 主按钮仅用于主要保存或创建动作；刷新、测试和分页使用次级按钮。
- 禁用态保留可辨识文本；错误状态提供可读原因。
- 使用原生语义控件和关联标签，支持键盘操作。

### 响应式

- 桌面端优先保证信息密度和列对齐。
- 中等宽度允许工具栏和变量标签自然换行。
- 窄屏将多列配置行改为纵向字段组，操作栏保持可见且不产生横向滚动。

## 数据流与兼容性

现有 `apiGet`、`apiPut`、`apiPost` 和 `apiDelete` 调用路径保持不变。加载、编辑、验证、保存和反馈流程不改变。结构调整后的选择器继续使用稳定的 ID 或明确的局部类名，避免事件绑定依赖纯视觉层级。

所有进入 `innerHTML` 的外部或可编辑数据必须经过 `escapeHtml` 或改用安全的 DOM 文本赋值。数值、枚举、电话号码、模板长度和标识符在客户端提供即时校验，但服务端校验仍是安全边界。

## 安全检查

- 运行依赖漏洞审计，区分直接依赖、传递依赖和仅开发环境影响。
- 检查模板字符串和 `innerHTML` 中是否存在未转义的接口数据，重点关注告警名称、错误消息、负责人、模板和历史结果。
- 检查 AccessKey、Secret、Token、手机号等敏感信息是否被明文返回、写入日志或注入页面。
- 检查告警注册的增删改、脚本应用、测试拨打和命令测试接口是否具备适当的身份校验与权限边界。
- 检查命令参数、URL、文件路径和远程请求输入是否可能造成命令注入、路径穿越、SSRF 或任意文件访问。
- 检查状态变更接口的请求方法、来源约束及 CSRF 风险。
- 对发现的问题按严重性、可利用条件、证据和修复建议记录；只在本次页面范围内直接修复低耦合且可验证的问题。

## 测试与验收

- 现有测试套件通过，或明确记录与本次无关的既有失败。
- 增加页面结构回归测试，覆盖模板区操作栏、标签关联、保存控件和关键转义点。
- 对安全修复增加最小回归测试，证明危险输入不会进入可执行或可注入上下文。
- 启动本地平台并检查目标页面：宽屏无异常大空白，控件对齐一致，保存和启用关系明确。
- 在窄屏检查无横向溢出、字段标签可理解、按钮可点击。
- 键盘焦点可见，加载、成功、失败和禁用状态均清晰。

## 完成标准

- 页面形成统一的专业运维控制台视觉语言，截图中暴露的布局问题全部消除。
- 业务接口和已有配置数据兼容，现有操作能力不减少。
- 安全检查有可复现证据；修复项有测试，未修复项给出明确风险与建议。
- 最新远端代码与原工作区修改均被保留，提交中不包含无关文件。
