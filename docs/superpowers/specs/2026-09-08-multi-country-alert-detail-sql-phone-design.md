# 多国一致性告警详情、SQL 编辑与电话闭环设计

## 背景与目标

当前告警注册页将同一次多国校验结果按 `mc_*` 条目重复聚合，但每条记录仍保留全部国家数据，导致条目名称、异常国家和详情内容错配。告警消息只链接到告警注册页根路径，无法定位具体运行与国家。详情区域虽然支持渲染 SQL 和差异行，但依赖回调携带 `sql/details`，缺失时没有明确说明。现有电话逻辑只计算并返回 `phoneNeeded`，并不能证明拨号已经发生。

本次改动需要：

1. 告警链接直接打开对应运行批次和国家，并自动展开详情。
2. 详情继续展示本次校验 SQL、异常统计和具体不一致数据。
3. 每个国家可独立编辑校验 SQL，保存后同步 n8n。
4. 每次真正播报的异常均触发一次电话，并防止回调重试造成重复拨号。
5. 不改变“两轮制”：首次异常只触发智能修复且不播报、不打电话；持续异常进入 `broadcast` 后才播报和拨号。

## 方案选择

采用告警注册页内的深链接方案，而不是新增独立页面或弹窗。链接使用现有 hash 路由的查询参数：

```text
#/alert-registry?runId=<run-id>&country=<country-code>
```

该方案保持现有导航和部署结构不变，同时允许 KN Chat、TV 和浏览器收藏稳定定位同一条详情。

## 历史数据模型与聚合

原始多国运行记录仍按一次运行保存，结构包含 `id`、`checkedAt`、`countries`、`broadcast`、`repairTriggered` 等字段。

`listAllHistory` 为每个 `mc_<country>` 条目生成展示记录时，只保留该国家对象：

```js
{
  ...run,
  entryId: `mc_${code}`,
  entryName,
  country: code.toUpperCase(),
  countries: [countryResult]
}
```

若某次运行没有对应国家结果，不为该条目生成记录。这样条目筛选、异常状态、SQL 和详情均来自同一个国家，不再交叉污染。

API 对外返回的展示记录增加稳定的 `detailKey`，由运行 ID 和国家代码组成。原始结果文件保持向后兼容，不迁移历史数据。

## 深链接和页面交互

页面加载时读取路由查询参数：

- `runId`：完整运行 ID；兼容消息中已有的短 ID 时，只在唯一匹配时定位。
- `country`：仅接受 `cn/id/mx/th/ph/pk`。

历史加载完成后：

1. 自动把条目筛选设置为 `mc_<country>`。
2. 在当前时间范围内查找运行；未找到时自动切换为“全部”。
3. 将目标运行排到可见页，滚动至目标卡片。
4. 自动展开目标国家的“校验语句与差异明细”。
5. 找不到记录时显示明确提示，不让页面空白或静默失败。

每个历史卡片提供“复制详情链接”按钮。告警消息模板板使用同一链接格式；平台构造链接时对参数编码。

## 详情内容契约

国家结果采用以下兼容结构：

```js
{
  code,
  label,
  mismatches: [{ check_item, mismatch_cnt }],
  sql,
  details: [{
    check_item,
    asset_item_no,
    user_id,
    src_value,
    dest_value
  }],
  detailsTruncated
}
```

页面按顺序展示：异常项汇总、本次执行 SQL、具体差异表。差异表继续分页，每国最多保留并展示 200 行。字段不存在时显示“无”，不拼接未转义 HTML。

旧记录没有 `sql` 或 `details` 时仍可打开：页面展示“该历史记录未保存本次 SQL”或“该历史记录只保存了异常数量，未保存具体差异”，避免把数据缺失误认为页面打不开。新回调原样保存这些字段。

## 校验 SQL 编辑

SQL 编辑入口只出现在 `mc_*` 条目的能力面板中，并只展示当前国家，不在每一行重复加载六国编辑器。

读取接口支持按国家获取：

```text
GET /api/multi-country/sql/:country
```

保存接口：

```text
PUT /api/multi-country/sql/:country
{ "sql": "..." }
```

服务端校验国家代码、非空、最大长度和只读查询形态。禁止多语句及明显写操作。更新 n8n 时读取最新工作流，替换目标国家 SQL，其他五国保持不变；n8n 更新成功后才返回成功。解析不再依赖固定空格和单引号格式，至少兼容对象字段顺序、单双引号和常见空白差异。接口不向前端返回 n8n API Key。

## 电话播报闭环

`appendCheckResult` 负责保存和判定需要拨号的国家，但实际拨号必须在回调处理链中执行并记录结果。对每个 `broadcast` 且电话已启用的国家：

1. 生成幂等键 `runId:country`。
2. 若该键已有完成或进行中的拨号记录，跳过重复触发。
3. 调用现有 `callMcPhone`，只传当前国家。
4. 将 `pending/succeeded/failed/skipped`、时间和脱敏后的结果写入运行记录。
5. 单个国家拨号失败不阻止历史回调成功，但 API 返回 `phoneDeliveries`，便于 n8n 和页面审计。

“每次播报”定义为每次新的运行 ID 中该国家进入 `broadcast`。同一运行因网络重试重复回调不会重复拨号。首次异常只在 `repairTriggered` 中，不拨号。

## 错误处理与安全

- 深链接参数无效时忽略参数并显示提示，不抛出页面级异常。
- SQL 同步失败时保留编辑内容和错误信息，不显示“已保存”。
- SQL 更新继续属于高风险管理接口；本次不扩展认证体系，但沿用现有网络限制，并禁止把凭据写入 SQL。
- 电话日志不返回完整手机号或云凭据。
- 历史文本、SQL、详情值和 ID 全部经过 HTML 转义。

## 测试与验收

- 单元测试复现同一多国运行被错误复制且国家数据未隔离的问题。
- 视图测试验证深链接参数、自动展开、空详情提示、复制链接和 HTML 转义。
- SQL 测试验证单国读取/更新、其他国家不变、格式兼容和危险 SQL 拒绝。
- 电话测试验证六国均遵守 `broadcast + phone enabled`、首次修复不拨号、同一运行重试不重复拨号、失败结果可审计。
- 全量 `npm test`、语法检查、差异检查和桌面浏览器验收通过后再提交交付。
